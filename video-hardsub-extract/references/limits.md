# 验证范围与已知限制

本文件记录这套脚本实际验证到什么程度。**单个样本通过不等于平台全部内容可用**，也不等于自动 OCR 零错误。

## 已验证

- 静音测试片（13 秒，6 条字幕）：时间轴边界误差 0.00 秒（容差 0.2 秒）；数字变化（12345→12346）、空白后重复、半秒内短字幕都正确保留。文字上有两处"中文与数字之间的空格"差异（`订单编号 12345` → `订单编号12345`），未视为时间轴问题。
- 五个平台各一条真实视频完成全片 OCR：快手、YouTube、抖音、B 站、X。参数与时长见下表。
- 抖音、快手、YouTube 做过逐张对照图 + 原帧复核的文字校对，并产出校对版；B 站只完成候选生成与部分抽查。
- 链接下载：快手、YouTube、B 站、X 成功；抖音提示需要新的 Cookie（`Fresh cookies (not necessarily logged in) are needed`），未重试。

## 已知缺陷与未通过项

1. **B 站 74.0–77.4 秒字幕漏检**：该段大字被候选筛选漏掉（原帧证据保留在验收目录），质量未完全通过，未补写；`review.py --apply` 只能合并/删除/改写已有候选，不能新增条目。
2. **X 的媒体文件 ID 与帖子 ID 不一致**：下载文件 ID `2114884114440757248` 与链接中 `2114884218375524847` 不同（时长与样本吻合，疑似重定向/转发），归属映射未核实。X 也没有做独立视觉校对。
3. **抖音链接下载依赖 Cookie**：本地视频识别与校对通过，但不能说成"抖音链接可直接下载"。需要登录/验证码时由用户本人在专用浏览器里完成，不导出他人浏览器凭据。
4. **平台适配只覆盖单条样本**：B 站、抖音的浏览器通道依赖页面结构，页面改版会失效；快手读取公开移动分享页的唯一 photo 对象，页面变化即报错而不是猜别的作品。
5. 没有逐帧核验所有平台的全部画面，没有做多语言/竖排/艺术字专项测试。
6. 未在市场上架，也未提交审核。

## 缓存与计时口径

- 缓存只复用**完整结果**，命中时输出目录带 `_cached`、`run.json` 标注"本次没有重新识别"，不得当作本次重新 OCR。
- 首次处理新视频没有缓存可命中，耗时就是真实识别耗时；缓存命中耗时不能与首次耗时混在一起比较。
- 相同裁剪像素的逐帧精确复用保留在实现里（`pixel_reuse_frames` 记录数量），但本批短视频样本实测基本不重复（静音片 78/78 帧、快手 101/101 帧均不重复），**不宣称因此变快**。
- 未采用 CPU 线程数调优和 4 进程并行：实测无稳定收益（10/2/4 线程 8.549/8.475/8.785 秒；4 进程与串行口径不同，不可比），且并行额外占内存。
- 不做近似去重、不降采样、不降模型、不截断片段来"提速"。
